# Deepen-existing candidates (draft)

Question: Which **existing** loops are underexposed or underpowered as weekly return reasons, and what **minimal deepenings** (visibility, grouping, continuity — not new jobs) might make them viable sticky candidates?

**Scope of “deepen”:** Ideas stay inside today’s jobs/surfaces (Discover Following / For you, Activity, Me, Title, User). Add visibility / grouping / continuity / change-true chrome only. No new user job, no new tabs, no personal watch diary (kill list #5). Net-new social or personal-ritual jobs → tickets 04/05.

**Inputs:** Inventory `01`; kill list `02`. Ideas only — not UX specs. No build commitment.

**Viable bar:** Fits taste-overlap primary job AND stays simple for a weekly-ish returner. Cadence: a few times a week when something meaningful changed; in-app only.

## Risk notes (keep with candidates into 06/07)

- **Graph density:** D1–D5 underperform for solo/small-graph users; D4 is the honesty valve, not a density fix.
- **Change-true ≠ obligation:** Chrome must only light when peers (or overlap set) actually acted — no “you haven’t visited” theater.
- **Surface budget:** All five ideas target existing tabs; none requires a new surface. Ticket 06 still checks stacking/complexity if several survive.
